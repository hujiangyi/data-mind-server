# DataMind 管理员快速开始

这份指南帮助第一次接手 DataMind 的管理员在最短时间内完成一次安全的配置。

## 你将完成什么

本次快速开始只做三件事：

1. 接入一个已经准备好的 MySQL 或 PostgreSQL 数据源；
2. 使用 AI 管家创建一个平台用户；
3. 为该用户准备“只能查询自己负责记录”的访问权限。

如果你还没有可用的数据源账号，请先准备一个能够被 DataMind 服务器访问的只读或受限账号。

## 1. 先确认数据源

在数据源管理页面完成：

```text
数据源名称
数据库类型
服务器地址和端口
数据库账号
数据库密码
```

点击测试连接，确认成功后同步数据库、数据表和字段。

开始权限配置前，至少要能在数据目录中找到：

```text
目标数据源
目标数据库
目标数据表
负责人字段或用户关联字段
```

如果找不到目标表，不要直接在 AI 管家里反复尝试。先回到数据源管理检查连接和同步结果。

## 2. 创建第一个平台用户

打开 **AI 管理**，输入：

```text
创建平台用户 zhangsan，真实姓名是张三，角色是普通用户。
```

系统会先显示将要创建的账号信息。确认账号、姓名和角色无误后，再确认执行。

创建完成后，将初始登录信息通过受信任的方式交给员工，并提醒员工首次登录后修改密码。不要把密码写入任务对话或截图。

## 3. 配置本人负责数据

继续创建一个新任务，输入：

```text
让账号 zhangsan 查询 crm 数据源、crm 数据库的 orders 表中
负责人字段等于其本人数据源身份的记录。
```

如果系统询问权限组，可以明确指定已有权限组，或者说明允许为这个用户创建一个专用权限组。

如果系统询问用户身份，需要从数据源用户目录中选择唯一身份。不要选择不确定或重复的身份。

## 4. 确认计划时看什么

确认前只看五项：

```text
用户是否是张三
数据源、数据库和表是否正确
范围是否是 OWNER，也就是本人负责记录
是否没有出现区域、部门、项目或全表条件
完成后是否有明确验证方法
```

计划中如果出现你没有提出的用户、数据表或更宽的访问范围，应取消并重新描述目标。

## 5. 等待和验证

授权后可能需要等待负责人字段分析和身份匹配。

完成后使用 zhangsan 的账号查询 orders 表，确认：

- 能看到负责人身份属于张三的记录；
- 看不到其他负责人的记录；
- 查询失败或分析未完成时，不会返回未过滤的全量结果。

如果分析需要人工复核、身份存在冲突或任务进入人工处理，请按页面提示进入数据范围管理或身份绑定页面。

## 6. 第一次使用的推荐任务

完成上面的流程后，可以尝试：

```text
检查账号 zhangsan 的数据源身份绑定是否完成。
```

```text
停用账号 temporary_user。
```

不建议第一次就使用模糊表达，例如“给销售开客户权限”。先使用明确的账号、数据源、数据库和表名，熟悉系统的提问方式。

## 7. 记住边界

DataMind 当前的数据范围只支持：

```text
负责人字段
→ 用户本人数据源身份
→ 精确匹配
```

不支持：

```text
华东区
部门
项目
租户
任意 SQL 条件
全表权限
```

完整概念和异常处理请参阅[管理员使用指南](admin-guide.md)。
