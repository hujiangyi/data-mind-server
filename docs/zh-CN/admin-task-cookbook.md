# DataMind 管理员任务配方

这些配方按管理目标组织。管理员先说目标，Agent 先查事实；只有出现歧义、风险或能力边界问题时，才请求选择或确认。

## 配方一：了解数据源

```text
了解所有已配置数据源，告诉我有哪些业务内容，哪些表适合配置本人相关数据。
```

系统会扫描数据源、数据库、表和字段元数据，推断业务主题、负责人字段候选和敏感字段风险。管理员不需要填写底层对象。

## 配方二：创建用户

```text
创建平台用户 zhangsan，真实姓名是张三，角色是普通用户。
```

确认账号、姓名、角色后执行。系统保持首次登录改密流程。

## 配方三：配置本人相关数据

```text
让张三可以查询与他本人相关的订单记录。
```

Agent 会从已发现目录中选择候选，并检查：

- 用户是否唯一；
- 订单候选是否唯一；
- 是否存在负责人字段；
- 数据源身份是否唯一；
- 当前表授权和 OWNER 状态；
- 是否需要分析或人工复核。

最终只能落为：

```text
OWNER / DIRECT / EQUALS
```

## 配方四：候选表选择

当“订单数据”匹配到多个表时，Agent 应展示可选项：

```text
1. crm / sales / orders：客户订单或交易记录，可评估 OWNER
2. archive / history / order_archive：历史归档，暂未识别负责人字段
```

管理员选择候选，不需要重新填写数据库和字段。

## 配方五：同名用户选择

```text
管理员：给张三配置刚才发现的订单数据。
Agent：发现两个张三，请选择账号和员工号。
管理员：选择 zhangsan（S-1024）。
```

任务会保留这个选择，后续不重新猜测。

## 配方六：查看权限

```text
检查张三当前有效权限、权限组和数据源身份绑定状态。
```

输出以控制库真实状态为准，区分“没有表授权”“OWNER 分析等待”“身份冲突”和“已验证可用”。

## 配方七：停用用户

```text
停用账号 temporary_user。
```

这是写操作，确认前检查目标账号，禁止停用当前操作管理员。

## 配方八：超出能力边界

以下需求当前不支持：

```text
让张三看华东区数据。
让销售部门只能看本部门客户。
让项目 A 成员看项目 A 的订单。
让张三看所有客户数据。
```

正确替代是：

```text
让张三只能查询负责人字段等于其本人数据源身份的记录。
```

Agent 不生成任意 SQL `WHERE` 条件，也不把用户组自动转换成数据范围。

## 配方九：分析或身份阻断

如果 OWNER 分析处于等待、复核或无效状态：

```text
查看这项 OWNER 任务的阻断原因，并告诉我下一步需要选择什么。
```

不要改成全表权限，不要扩大数据库账号权限，不要覆盖冲突身份。需要人工判断时进入数据范围管理或身份绑定页面。

## 配方十：权限申请

```text
查看待审批权限申请，按风险和当前有效权限给我整理审批候选。
```

Agent 可以整理事实和风险，但最终批准仍由管理员完成。高风险权限不能自动批准。

## 配方十一：失败和回滚

```text
查看任务执行到哪一步，验证失败的原因是什么。
```

可选择：

```text
继续补齐候选
查看精确管理页面
回滚已完成动作
转人工处理
```

任务只有通过执行后真实状态验证，才算成功。

## 最短工作方式

```text
先了解数据源，再告诉我你发现的可管理对象。
```

```text
给张三配置其中的订单数据，只允许本人身份匹配的负责人记录。
```

```text
执行前展示影响范围，执行后验证并告诉我是否可回滚。
```
