# DataMind 管理员 AI-first 指南

DataMind 的管理员工作不应是记住一串菜单和字段，而是表达一个业务目标。系统会先扫描已配置数据源的真实结构，把技术元数据翻译成可理解的业务线索，再由管理员确认必要的候选和风险。

这套指南只保留一个原则：**AI 负责发现、整理、编排和验证；管理员负责连接准确性、歧义选择、高风险审批和人工接管。**

## 1. 管理员先做什么

管理员只需要人工完成数据源连接本身：

- 配置 MySQL 或 PostgreSQL 的地址、端口、账号、密码和网络要求；
- 测试连接，确保 DataMind 服务器能够访问；
- 处理数据库账号、TLS、网络白名单等基础设施问题。

连接成功后，不需要再手工填写数据库、数据表或字段。打开 **AI 管理**，说：

```text
了解现在已经配置的数据源，告诉我有哪些业务内容，哪些表适合配置“与用户本人相关的数据”。
```

Agent 会读取数据库目录、数据表、字段名称、字段注释、主键和必要的元数据，不把原始业务样本放进普通对话记忆。识别结果是渐进式的：部分数据源暂时不可读时，已读到的结构仍然可以继续使用。

## 2. AI 会怎样理解数据源

AI 不要求管理员先知道物理结构。它会按以下顺序工作：

```text
读取数据源
→ 发现数据库和数据表
→ 读取字段元数据
→ 推断业务主题和可能的负责人字段
→ 标记敏感字段风险
→ 生成可选择的管理候选
→ 在后续任务中复用已确认事实
```

例如，系统发现 `orders` 表和 `owner_user_id` 字段时，会把它解释为“可能是客户订单或交易记录，发现了可评估本人负责数据的字段”。这只是基于真实字段名称和注释的候选判断，不会把模型猜测直接变成权限策略。

## 3. 当前唯一的数据范围能力

DataMind 当前只支持：

```text
OWNER / DIRECT / EQUALS
负责人字段 = 当前用户在该数据源中的唯一身份
```

“与我有关的数据”就是这条可验证的身份关系。它不是区域、部门、项目或任意业务标签。

支持：

```text
让张三查询订单表中与他本人相关的记录。
```

不支持：

```text
让张三查看华东区数据。
让销售部门只能看本部门客户。
让项目 A 的成员查看项目 A 的订单。
给订单权限加 WHERE region = '华东'。
```

遇到越界要求，Agent 必须直接说明限制，并给出可执行替代：

```text
当前数据范围能力只支持“负责人字段与用户本人数据源身份精确匹配”。
系统不能按华东区、部门或项目配置范围。
是否改为：让张三只能查询负责人字段等于其本人身份的记录？
```

“销售组”可以作为用户集合存在，但组内每个人仍然只能查看与自己身份匹配的记录，不能因此得到组内共享的全部数据。

## 4. 管理常规人员和权限

管理员可以直接描述目标：

```text
创建平台用户 zhangsan，真实姓名是张三，角色是普通用户。
```

```text
停用账号 temporary_user。
```

```text
让张三可以查询与他本人相关的订单记录。
```

最后一个请求不需要先写数据源、数据库、表和字段。Agent 会从已发现目录中给出候选。如果只有一个候选，可以继续生成计划；如果有多个候选，页面会展示选项，管理员只需点击目标。

写操作必须经过确认。计划会展示目标用户、权限组、真实数据表、OWNER 策略、身份匹配证据、风险、验证方法和回滚方式。确认后系统才执行。

## 5. 什么时候 Agent 必须反问

Agent 不会让模型猜测关键对象。以下情况必须停在 `NEEDS_CLARIFICATION`：

- 同名用户或权限组；
- 多个候选数据表；
- 无法判断管理员是新增、撤销还是查看；
- 目标表没有可靠负责人字段；
- 负责人识别置信度低于安全阈值；
- 数据源用户目录中存在多个冲突身份；
- 请求包含区域、部门、项目或全表语义；
- 请求影响大量用户或整库权限。

反问应尽量是选择题，而不是开放式填空。例如：

```text
发现两个“订单”候选，请选择：
1. crm / 业务库 / orders：客户订单或交易记录，可评估 OWNER
2. finance / 财务库 / order_archive：历史归档，暂未识别负责人字段
```

管理员选择后，任务会记住选择，不需要重复解释前文。

## 6. OWNER 配置的完整流程

```text
识别用户
→ 从已发现目录中定位数据表
→ 创建或复用权限组
→ 授权数据表
→ 触发现有 OWNER 分析任务
→ 识别真实负责人字段
→ 匹配用户的数据源身份
→ 激活 OWNER / DIRECT / EQUALS
→ 重新读取真实状态验证
```

新表授权会先进入 `PENDING_ANALYSIS`。分析未激活、需要复核、身份冲突或验证失败时，普通用户查询必须保持阻断，不能回退到未过滤查询。低置信度结果进入复核流程，不能由 Agent 自动覆盖。

管理员仍可按现有规则查看全部数据。普通用户只能查看负责人字段等于其本人数据源身份的记录。

## 7. 三类任务记忆

每个管理员任务都有独立记忆：

### 对话记忆

保存当前目标、已选用户、已选候选、未解决问题和明确拒绝的越界要求。

### 执行记忆

保存任务 ID、计划、步骤、前置条件、工具结果、检查点、重试次数、补偿动作和验证结果。服务重启后可以从检查点继续。

### 领域事实

只以控制库真实状态为准，保存用户 ID、权限组 ID、数据源 ID、表 ID、分析任务 ID、身份绑定状态和权限状态。模型的文字描述不是事实。

密码、API Key、外部身份值和原始业务样本不进入普通对话、计划或日志。

## 8. 失败、补偿和人工接管

临时网络错误可以有限重试；确定性错误不重复重试；计划执行后验证失败最多进行一次受限修正。补偿失败或再次验证失败时，进入 `NEEDS_HUMAN`，保留半完成状态和完整审计。

管理员可以：

```text
补充候选
查看任务事实
进入数据源管理
处理数据范围复核
处理身份绑定
查看审批中心
回滚计划
人工接管
```

进入精确管理页面不是系统失效，而是把需要人工判断的工作交还给管理员。数据源连接仍需管理员准确处理，权限申请仍需管理员最终审批。

## 9. 权限申请

员工申请进一步权限时，管理员在审批中心查看申请人、当前有效权限、目标数据表、OWNER 状态和身份绑定状态。高风险申请不能因为来自 AI 或 MCP 就自动批准。

管理员应拒绝把区域、部门、项目或全表需求伪装成 OWNER 权限。审批完成后，用目标账号实际查询验证，而不是只看页面成功提示。

## 10. 面向管理员的最短表达

推荐这样说：

```text
先了解现在的数据源，告诉我哪些内容适合做本人相关数据。
```

```text
给张三配置刚才发现的订单数据，但只能看负责人是他本人身份的记录。
```

```text
检查张三当前有效权限和数据源身份绑定状态。
```

管理员不需要学习数据库字段命名；只有 Agent 无法从真实结构安全判断时，才会展示候选并请求选择。
