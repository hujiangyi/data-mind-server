# DataMind 管理员使用指南

DataMind 的目标不是让管理员记住更多菜单，而是让管理员用一句清楚的话表达管理目标，系统负责整理信息、识别对象、检查边界、准备变更并帮助完成验证。

你只需要记住三件事：

1. **数据源连接需要管理员准确配置。** 数据库地址、账号、密码、网络和加密要求属于基础设施信息，仍然由管理员在数据源页面处理。
2. **人员、常规授权和“与本人相关的数据”可以先交给 AI 管家。** 你描述想达到的结果，系统会先查清楚当前情况，再告诉你需要补充什么或准备如何修改。
3. **涉及写入的计划必须由管理员确认。** 系统不会因为听懂了一句话就直接扩大权限；执行后还会重新检查实际结果。

这套方式让管理员从重复的配置劳动中解脱出来，同时把真正需要判断的事项留在管理员手中。

## 一、五分钟开始使用

### 第一步：准备数据源

先在数据源管理中添加并测试需要使用的 MySQL 或 PostgreSQL 数据源，然后同步数据库、数据表和字段信息。

这是管理员必须准确完成的一步，因为系统需要知道：

- 数据源是否可连接；
- 哪些数据库和表可以被管理；
- 表中实际有哪些字段；
- 数据源用户目录中有哪些身份。

浏览器能打开管理页面，不代表服务器能访问业务数据库。连接测试和元数据同步都通过后，再开始配置人员权限。

### 第二步：打开 AI 管家

在管理员页面进入 **AI 管理**，直接描述要完成的目标。建议在一句话中尽量带上：

- 用户账号、真实姓名或员工号；
- 数据源名称；
- 数据库名称；
- 数据表名称；
- 是新增权限、停用账号，还是查询当前状态；
- 如果涉及数据范围，明确说“只能查询负责人字段等于本人身份的记录”。

例如：

```text
让账号 zhangsan 查询 crm 数据源、crm 数据库的 orders 表中
负责人字段等于其本人数据源身份的记录。
```

### 第三步：补充问题，而不是重新开始

如果系统发现两个同名用户、多个候选表或缺少数据源信息，它会停下来提问。你只需要回答问题，系统会保留当前任务中已经确认的内容。

例如：

```text
管理员：给张三开通客户数据权限。
AI 管家：发现两个同名用户，请补充账号、员工号或真实姓名。
管理员：账号是 zhangsan，员工号 S-1024。
```

后续回答会继续当前任务，不需要把最初的完整请求再说一遍。

### 第四步：核对计划

在确认前，重点看：

- 用户是否正确；
- 数据源、数据库和表是否正确；
- 是新增权限还是其他操作；
- 数据范围是否明确为“与用户本人身份匹配”；
- 是否只影响预期的用户和表；
- 系统是否说明了完成后的验证方法。

内容不对时，可以继续补充或取消任务；不要为了让系统继续而忽略对象错误。

### 第五步：确认并验证

确认后，系统会执行已列出的变更，并重新检查用户、权限和数据范围状态。

如果 OWNER 分析或身份匹配仍在进行，普通用户不会因此获得未过滤的数据。等待完成后，再使用目标用户账号进行实际查询验证。

## 二、DataMind 的三个独有概念

### 1. “与我有关的数据”

在 DataMind 中，“与我有关”不是由 AI 根据业务常识猜出来的标签，而是一种可以验证的关系：

```text
数据表中的负责人字段
= 当前用户在该数据源中的唯一身份
```

例如，订单表中的 `owner_user_id` 是 `u-1024`，张三在该数据源用户目录中的身份也是 `u-1024`，那么张三可以查询负责人为 `u-1024` 的订单。

这意味着：

- 张三只能看到与张三身份匹配的记录；
- 同一个权限组中的其他用户不会自动看到张三的记录；
- “销售组”可以管理一批用户，但不会把他们变成一个共享的全量数据范围；
- 没有可靠负责人字段或身份无法唯一匹配时，系统会阻断访问或要求人工处理。

### 2. 权限组不是数据范围

权限组解决的是“哪些用户拥有某项访问资格”。数据范围解决的是“这些用户进入数据后能看到哪些记录”。

因此：

```text
把张三加入销售组
```

不等于：

```text
张三可以看到销售组的全部数据
```

如果该权限组访问的是 OWNER 数据，组内每个人仍然只能查询负责人字段等于自己数据源身份的记录。

### 3. 任务记忆

AI 管家不会把每次对话当成孤立问题。一个管理任务会记住：

- 已经确认的用户；
- 已经确认的数据源、数据库和表；
- 管理员选择的候选对象；
- 尚未补充的信息；
- 已经拒绝的越界要求；
- 已经完成、等待或需要人工处理的步骤。

任务完成后，系统保存的是便于追踪的管理记录和脱敏信息，不会把数据库密码、API Key 或原始业务样本当作普通对话内容保存。

## 三、AI 管家适合处理什么

### 可以直接描述的任务

当前 AI 管家适合处理以下常见目标：

- 创建平台用户；
- 停用非当前管理员账号；
- 创建或使用权限组；
- 把目标数据表授权给权限组；
- 为用户配置“负责人字段等于本人数据源身份”的数据访问；
- 在 OWNER 配置任务中检查数据范围分析和数据源身份是否准备完成；
- 把无法自动确认的问题整理成待人工处理事项。

### 仍然需要管理员精确处理的任务

以下事项不能只依赖一句自然语言：

- 添加、修改、测试数据源连接；
- 修改数据库账号、密码、网络白名单或 TLS 配置；
- 审核低置信度的负责人字段识别；
- 解决一个用户在同一数据源中的多个冲突身份；
- 审批高风险或进一步权限申请；
- 处理自动执行后无法验证或无法补偿的异常；
- 设计区域、部门、项目、租户等当前系统没有提供的数据范围。

AI 管家会把这类事项解释清楚，并引导你进入对应的精确页面。

## 四、如何说，系统更容易一次完成

### 推荐表达结构

```text
对谁
要做什么
针对哪个数据源、数据库和表
希望看到什么范围
```

推荐写法：

```text
让账号 zhangsan 新增 crm 数据源、crm 数据库、
orders 表的本人负责数据查询权限。
```

```text
创建平台用户 qa_user，真实姓名是测试用户，角色是普通用户。
```

```text
检查账号 zhangsan 当前有哪些有效数据权限，以及身份绑定是否完成。
```

```text
停用账号 temporary_user。
```

### 不够明确的表达

下面的说法通常需要继续补充：

```text
给张三开客户权限。
```

因为系统还不知道：

- 哪个张三；
- 哪个数据源；
- 哪个数据库和表；
- 是新增权限还是查询当前状态；
- “客户权限”是否指本人负责数据。

可以改成：

```text
让账号 zhangsan 查询 crm 数据源 crm 数据库 customers 表中
负责人字段等于本人数据源身份的记录。
```

## 五、数据范围的正确理解

当前 DataMind 只支持一种受限的数据范围方式：

```text
OWNER
```

它通过固定的本人身份匹配来实现：

```text
负责人字段
→ 直接映射到数据源用户身份
→ 与当前用户身份相等
```

系统会先确认目标表和负责人字段真实存在，再检查字段是否可以比较、负责人识别是否可靠、用户在数据源中是否只有一个有效身份。

只有这些条件都满足，系统才会允许数据范围进入可用状态。分析未完成、分析结果需要复核、身份存在冲突或验证失败时，查询会保持受限，不会退回成未过滤查询。

## 六、明确不支持的要求

以下要求超出当前能力：

```text
让张三看华东区数据。
让销售部门只能看本部门客户。
让项目 A 的成员看项目 A 的订单。
让张三看所有客户数据。
给订单权限加 WHERE region = '华东'。
```

系统不能按区域、部门、项目、租户、组织层级或任意业务条件配置数据范围，也不会把自然语言直接转换成任意 SQL 条件。

正确的反馈应该是：

```text
当前数据范围只支持“负责人字段等于用户本人数据源身份”。
系统不能按华东区、部门或项目配置范围。
如果你的目标是限制张三查看自己负责的记录，
可以改为描述具体用户、数据源、数据库、表和负责人字段。
```

## 七、确认前后会发生什么

### 确认前

AI 管家会先整理：

- 目标用户；
- 权限组；
- 数据源、数据库和表；
- 当前已有权限；
- 数据范围准备情况；
- 身份匹配情况；
- 可能产生的影响；
- 完成后如何验证。

如果对象不唯一或信息不完整，系统会提问，不会用猜测替代事实。

### 确认后

系统会按计划完成必要的人员、权限组、表授权和 OWNER 准备工作，然后重新检查实际状态。

管理员看到“已完成”前，系统应能够说明：

- 目标用户仍然存在且状态正确；
- 权限组关系正确；
- 表授权正确；
- 数据范围已经可用，或者仍在等待分析；
- 身份绑定有效；
- 没有意外扩大到其他用户或数据表。

### 仍在等待时

如果页面显示正在等待分析，表示权限关系已经准备好，但负责人字段识别或身份匹配还没有达到可用条件。

这不是失败，也不是可以跳过的提示。分析完成前，普通用户查询仍然受到保护。

## 八、什么时候进入精确管理页面

可以把 AI 管家理解为“常规工作的入口”，把精确管理页面理解为“需要管理员判断的工作台”。

遇到以下情况时，应进入精确页面：

| 情况 | 推荐入口 |
| --- | --- |
| 数据源无法连接或需要改密码 | 数据源管理 |
| 数据库、表或字段没有同步 | 数据源管理、数据目录 |
| 需要确认某个用户当前已有权限 | 用户管理、权限管理 |
| OWNER 字段识别不确定 | 数据范围管理 |
| 用户存在多个数据源身份 | 身份绑定 |
| 员工申请更进一步权限 | 审批中心 |
| 任务执行后状态不一致 | AI 管家任务详情、精确管理 |
| 需要检查完整审计记录 | 对应审计或管理页面 |

进入精确页面不是系统失败，而是系统在把需要人工判断的事项交还给管理员。

## 九、权限申请如何处理

员工申请进一步权限时，管理员仍然拥有最终决定权。请在审批中心查看并整理：

- 申请人和账号状态；
- 当前有效权限；
- 目标数据源、数据库和表；
- 当前 OWNER 数据范围状态；
- 身份绑定状态；
- 申请是否提出了当前不支持的区域、部门、项目或全表范围。

管理员批准前，应确认申请不会改变当前数据范围边界。批准后，要使用目标员工账号实际查询验证，而不是只看页面上的成功提示。

## 十、常见问题

### 为什么我说了“客户数据”，系统还要问表名？

因为“客户数据”可能对应多个数据源、数据库或数据表。权限配置必须落到唯一对象，系统不能凭名称猜测。

### 为什么同一个权限组里的用户看不到彼此的数据？

权限组只表示访问资格。OWNER 数据范围仍然按每个人自己的数据源身份过滤。

### 为什么不能配置“华东区”？

因为当前系统没有区域维度的数据范围模型。现在只能支持负责人字段与用户本人身份匹配。

### 为什么授权后还不能马上查询？

新授权需要先完成负责人字段分析和身份匹配。分析未达到可用条件前，系统会阻断未过滤查询。

### 为什么 AI 管家没有直接修改数据源密码？

数据源连接属于基础设施配置，需要管理员准确确认连接参数、网络和安全要求，因此保留在精确管理页面。

## 十一、管理员日常检查清单

配置完成后，建议按下面顺序快速确认：

```text
□ 数据源连接测试通过
□ 数据库、表和字段已经同步
□ 目标用户唯一且账号状态正常
□ 目标数据表唯一
□ 目标权限范围明确为本人身份匹配
□ OWNER 分析已经可用，或正在明确等待
□ 数据源身份唯一且没有冲突
□ 计划影响范围与预期一致
□ 使用目标用户账号完成实际查询验证
□ 异常任务已经回滚或交给人工处理
```

更多可直接套用的说法，请参阅[管理员任务配方](admin-task-cookbook.md)；第一次安装和配置请参阅[管理员快速开始](admin-quickstart.md)。
